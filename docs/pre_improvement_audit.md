# AI-QTriage Codebase Audit (Pre-Improvement)

This document lists the audited issues, their severity, files involved, current behavior, and recommended corrections prior to applying fixes to the Twilio delivery pipeline and SOS countdown system.

| Issue | Severity | File | Current Behavior | Recommended Correction |
|---|---|---|---|---|
| Twilio alert missing on countdown natural expiry | **CRITICAL** | [`backend/services/sos_service.py`](file:///c:/Users/santh/Capstone%20Project%20Code/backend/services/sos_service.py) | Polling updates case status to `"dispatched"` in the database but never triggers the Twilio REST API when the countdown reaches 0 naturally. | Check `sos_delivery_mode` on natural countdown expiry; if `"twilio_test"`, invoke `twilio_service.send_test_sos_message` and update case and event documents. |
| Potential duplicate Twilio messages | **HIGH** | [`backend/main.py`](file:///c:/Users/santh/Capstone%20Project%20Code/backend/main.py) | The `/api/cases/{case_id}/sos/demo/respond` endpoint triggers a Twilio message without verifying if the event has already been processed or remains active. | Add check that active `countdown` event exists in `db.sos_events` for the case before sending the message, and log warning/abort if none exists. |
| UI does not display Twilio Message SID and failure details | **MEDIUM** | [`frontend/app/cases/[id]/page.tsx`](file:///c:/Users/santh/Capstone%20Project%20Code/frontend/app/cases/%5Bid%5D/page.tsx) | The frontend displays the final SOS status but does not show detailed error information or Twilio message IDs returned by the API. | Update the SOS status UI rendering to show Message SID, delivery status, and any error message if Twilio fails. |
| Lack of explicit dataset metadata file | **MEDIUM** | `ml/models/` | Metadata is stored inside a nested run directory but not in the root model folder `ml/models/yolo11_metadata.json` for easy retrieval. | Create and maintain `ml/models/yolo11_metadata.json` mapping all training and provenance fields. |
| Research dashboard lacks ablation values | **MEDIUM** | [`frontend/app/research/page.tsx`](file:///c:/Users/santh/Capstone%20Project%20Code/frontend/app/research/page.tsx) | Modality ablation metrics (macro precision, recall, ECE, Brier) are omitted from the UI visualization despite backend availability. | Update research dashboard components to render all detailed modality performance metrics and perturbation degradations. |
